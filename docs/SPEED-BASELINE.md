# Decode speed baseline

How long SageThumbs 2K takes to turn each format into a 256 px thumbnail, and how long
Windows' own codec takes on the same file. Generated by `scripts\speed-report.ps1`.

**These numbers are specific to the machine below.** Comparing them against a run on
different hardware, or against a machine without the same codec extensions installed,
measures the hardware rather than the software.

| Codec extensions | AV1VideoExtension 2.0.24.0, HEIFImageExtension 1.2.36.0, HEVCVideoExtension 2.5.28.0, RawImageExtension 2.5.24.0, WebpImageExtension 1.2.31.0 |

## How to read it

* **Ours** and **Windows** are milliseconds to decode and fit to a 256 px box. Both are
  measured in-process and take the fastest of 5 runs, so neither carries process
  startup and background load is squeezed out as far as it can be.
* **Windows** is blank where WIC cannot open the format at all. That is most of what this
  product is for, and it is a fact about the format, not a score.
* **x** is ours ÷ Windows, and it is **the column to trust**: the two sides of each row are
  measured seconds apart, so background load hits both equally and cancels. The absolute
  milliseconds are honest but wander with whatever else the machine is doing.
* Ratios over a few milliseconds of absolute difference are not worth reading — a 7x on a
  3 ms decode is 3 ms.
* Sizes: **small** 320×240 (0.08 MP), **medium** 1600×1200 (1.9 MP), **large** 4000×3000
  (12 MP), all the same source picture. **single** means the format cannot be synthesised,
  so it is the one real corpus sample at whatever size it is.

## Summary

* 374 samples measured across 230 formats.
* 103 have a Windows equivalent; **44 of those are at least as fast as Windows**.
* 271 have no Windows equivalent at all — for those, this is the only record that exists.
* Median ratio where a comparison exists: **1.21x**.
